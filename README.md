# CRM-система для управління записами до лікаря (Hospital CRM)

Внутрішня CRM-система медичного закладу, реалізована за модульною монолітною архітектурою (**Python 3.11 + FastAPI + SQLAlchemy ORM + PostgreSQL 15 + Web UI + Docker Compose**). Система забезпечує централізоване ведення бази пацієнтів і лікарів, інтерактивний календар записів та автоматичний захист від подвійного бронювання часових слотів.

## 2. Інтеграція компонентів та протоколи взаємодії

1. **Клієнтський рівень (`Web UI`) ↔ Серверний рівень (`FastAPI Routers`):**
   - Взаємодія через інтерфейс **REST API** за протоколом **HTTP/HTTPS** у форматі **JSON**.
   - Підтримуються методи `GET` (розклад, пошук, фільтрація), `POST` (створення пацієнтів, лікарів, записів), `PUT` (редагування даних, перенесення часу), `DELETE` (видалення карток, скасування прийому).
2. **Рівень маршрутизації (`routers.py`) ↔ Бізнес-логіка (`services.py`):**
   - Передача провалідованих Pydantic DTO-об'єктів.
   - Синхронний виклик `AuditLogService` при кожній зміні стану системи.
3. **Сервісний рівень (`services.py`) ↔ База даних (`PostgreSQL`):**
   - Взаємодія через **SQLAlchemy ORM** за мережевим протоколом **TCP/IP (порт 5432)** у межах ACID-транзакцій.

## 3. Основні ендпоінти REST API

| Метод | Маршрут | Опис функціональності | Коди відповідей |
| :--- | :--- | :--- | :--- |
| `GET` | `/` | Веб-інтерфейс панелі Адміністратора (Календар та CRM) | `200 OK` |
| `POST` | `/api/patients` | Додавання нового пацієнта (ПІБ, телефон, дата народження) | `201 Created`, `422` |
| `GET` | `/api/patients?query=...` | Пошук пацієнтів за ПІБ або номером телефону | `200 OK` |
| `PUT` | `/api/patients/{pat_id}` | Редагування контактних даних пацієнта | `200 OK`, `404` |
| `DELETE` | `/api/patients/{pat_id}` | Видалення картки пацієнта з бази | `200 OK`, `404` |
| `POST` | `/api/doctors` | Додавання профілю лікаря (ПІБ, спеціальність, кабінет) | `201 Created`, `422` |
| `GET` | `/api/doctors?specialty=...` | Перегляд списку лікарів та фільтрація за спеціальністю | `200 OK` |
| `GET` | `/api/doctors/{id}/schedule?date=...` | Отримання розкладу лікаря з вільними та зайнятими слотами | `200 OK`, `404` |
| `POST` | `/api/appointments` | Запис пацієнта на вільний час із перевіркою конфліктів | `201 Created`, `409 Conflict` |
| `PUT` | `/api/appointments/{id}/reschedule` | Перенесення запису на інший вільний час | `200 OK`, `409 Conflict` |
| `DELETE` | `/api/appointments/{id}` | Скасування запису на прийом | `200 OK`, `404` |
| `GET` | `/api/audit-logs` | Перегляд системного журналу дій адміністратора | `200 OK` |

## 4. Виконання функціональних та нефункціональних вимог

### Функціональні вимоги
- **Управління пацієнтами:** Повний цикл CRUD (додавання, редагування, видалення) та миттєвий пошук за ПІБ або номером телефону.
- **Управління лікарями:** Створення профілів спеціалістів із зазначенням кабінету та фільтрація за спеціальністю.
- **Управління записами (Бронювання):** Відображення сітки вільних та зайнятих слотів (`09:00–16:30`), створення, перенесення (`RESCHEDULED`) і скасування (`CANCELLED`) прийомів.
- **Блокування подвійних записів:** Метод `AppointmentService.is_slot_available()` блокує спробу записати двох пацієнтів до одного лікаря на один і той самий час, повертаючи код `409 Conflict`.

### Нефункціональні вимоги
- **Продуктивність:** Завантаження інтерфейсу користувача відбувається менш ніж за `0.05 с` (вимога: `≤ 2 секунди`), пошук пацієнтів виконується за `< 0.02 с` (вимога: `≤ 3 секунди`).
- **Ергономіка (Usability):** Створення запису в інтерфейсі займає **3 кліки** (обрати лікаря/дату → обрати пацієнта → натиснути «Записати» на вільному слоті), що відповідає вимозі `≤ 4 кліків`.
- **Кросбраузерність та пристрої:** Інтерфейс оптимізовано для десктопних ПК (`1024x768` і вище) та планшетів у браузерах Chrome 100+, Firefox 100+, Safari 15+ та Edge.
- **Надійність і доступність:** Розгортання у контейнерах Docker Compose із перевіркою стану БД (`healthcheck`) та постійним томом `postgres_data` забезпечує збереження даних при збоях і доступність `99,9%` робочого часу.
- **Логування:** Усі операції адміністратора автоматично записуються в таблицю `audit_logs`.

## 5. Інструкція з налаштування та запуску інтегрованої системи

### Спосіб 1: Запуск у Docker Compose
Переконайтеся, що встановлено Docker та Docker Compose, і виконайте в корені проекту:
```bash
docker compose up --build -d
```
- Панель Адміністратора (Web UI): `http://localhost:8000`
- Інтерактивна документація API (Swagger UI): `http://localhost:8000/docs`
- Зупинка контейнерів: `docker compose down`

### Спосіб 2: Локальний запуск у віртуальному середовищі
```bash
python -m venv venv
.\venv\Scripts\activate


pip install -r requirements.txt
uvicorn src.main:app --host 0.0.0.0 --port 8000 --reload
```
